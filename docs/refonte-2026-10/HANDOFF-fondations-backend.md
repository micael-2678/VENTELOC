## 2. API : ce qui change (à répercuter côté front)

### Nouveau / modifié
- `POST /auth/register` → `{token, user, email_verification_required: true}` ; `user.email_verified = false`. Un seul e-mail (« Confirmez votre adresse e-mail », lien `SITE_URL/confirmer-email/:token`).
- `POST /auth/verify-email {token}` → `{verified, email, role}` (idempotent : `already_verified`). **Page front `/confirmer-email/:token` à créer.**
- `POST /auth/resend-verification` (authentifié, 429 si < 1 min) → `{sent, expires_in}` ou `{already_verified}`.
- `POST /auth/login` : pour un **admin** → `{otp_required: true, email, expires_in: 600, resent}` (pas de jeton) ; puis `POST /auth/login/verify {email, code}` → `{token, user}`. Pour les autres rôles : inchangé (`{token, user}`), `user.email_verified` présent. **LoginPage : afficher le champ code quand `otp_required`.**
- `POST /auth/change-password` → `{message, token}` : **remplacer le jeton stocké** (les anciens sont révoqués).
- `DELETE /auth/account` (corps JSON `{password}`) → anonymisation ; `GET /auth/export` → JSON. **Boutons à ajouter dans ProfilePage.**
- Tant que `email_verified` est faux : 403 avec `detail` commençant par « Confirmez d'abord votre adresse e-mail » sur `POST /companies/{id}/contact`, `POST /messages` (repreneur), `POST /alerts`, `POST /dataroom/{id}/request-access`, `POST /signatures/request-code`, signature du mandat ; une annonce créée reste `draft` avec `blocked_reason: "email_not_verified"`. **Bandeau clair + bouton « Renvoyer l'e-mail » dans l'espace connecté.**
- `POST /companies/{id}/contact` et `POST /messages` n'exigent **plus** l'identité vérifiée (elle l'est au NDA / mandat via `request-code`).
- `GET /config` → `{site_name, site_url, seller_commission, commission_mode:'simple', commission_payer:'cedant', commission_scale:{mode, rate_percent:6, rate_percent_above:3, threshold:1000000, minimum_ht:4000, vat_rate:0.2, payer, terms_version:'v2'}, commission_scale_text, commission_terms_version}`. Plus de `buyer_credits`, `free_mode`, tranches. **`frontend/src/lib/offer.js` à aligner.**
- `commission_info` sur chaque annonce → `{payer:'cedant', rate_percent_ht:'6 %', estimate_ht, estimate_ttc, minimum_ht:4000, terms_version:'v2', base}` ; `payer:'repreneur'` + `terms_version:'v1'` uniquement pour les anciennes annonces (bandeau conservé sur `CompanyDetail`).
- `POST /seller/mandat/{id}/sign {otp_code}` : **`commission_payer` n'est plus accepté ni nécessaire** (ignoré s'il est envoyé) ; réponse `commission_payer:'cedant'`. **MandatePage : retirer le choix du débiteur.** `GET /seller/mandat/status/{id}` : `mandat.commission_terms_version`.
- `GET /admin/stats` → `{total_companies, published_companies, total_users, invoices_count, total_revenue (HT facturé), paid_revenue}`.
- `GET /health` → `{status, db, jobs_age_seconds, disk_free_mb, s3, version}` (503 si `db:'ko'`).
- E-mail de code de signature : objet « Votre code de signature » (code dans le corps uniquement).

## 3. Pour les modules (`events.py`, `estimator.py`, `closing.py`, `veille.py`, `transmissibility.py`)

- Import : `from server import db, get_current_user, require_admin, next_sequence, claim_once, email_user, email_admin, limiter, site_url, site_name, _parse_dt, require_verified_email, is_user_verified, LEGAL_ENTITY, PartyLabels, display_name, scrub_contacts`. `router = APIRouter()` sans préfixe (chemins relatifs à `/api`).
- Tâches : `async def daily_job(now)` (ou sans argument) ; idem `weekly_job`, `monthly_job`. Elles sont exécutées une fois par jour / semaine ISO / mois (`claim_once`), et **toujours** par `POST /admin/jobs/run` (`force=True`). Résultat attendu : un entier (ou tout objet sérialisable en chaîne).
- Limitation de débit (events, 60/min) : `@router.post("/events")` + `@limiter.limit("60/minute")` et un paramètre **nommé `request: Request`** dans la signature (exigence slowapi). Pensez à décorer dans cet ordre (route au-dessus).
- E-mails : `await email_user(user_id, "nom_du_gabarit", **valeurs)` exige que le gabarit existe dans `business_model.EMAIL_TEMPLATES` ; pour vos propres gabarits, utilisez `send_brevo_email(to, name, subject, html, unsubscribe_url=...)` ou faites-les ajouter via ce handoff. `{site_name}` est injecté automatiquement. E-mails non transactionnels : passez `unsubscribe_url=` (respecte `notifications_opt_out`).
- Facture / closing (`closing.py`) : `next_sequence("invoice_<année>")` existe ; `db.invoices` est lu par `GET /admin/stats` (champs `status` ∈ {draft, issued, paid, cancelled…}, `total_ht`) et par `GET /auth/export` (`debtor.user_id`). Le débiteur est **toujours** le cédant (`business_model.COMMISSION_PAYER`).
- Ordre des routes : les routeurs de modules sont inclus **après** toutes les routes de `server.py` ; un chemin identique serait masqué par celui de `server.py`. Aucun des chemins listés ci-dessus (`/admin/invoices`, `/closing/...`) n'est plus défini dans `server.py` : libre pour `closing.py`.
