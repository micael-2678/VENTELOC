## 2. À appliquer ailleurs (fichier → fonction → code)

### 2.1 Backend `server.py` — chantier « parcours repreneur » (le front lit déjà ces formes, avec repli sur les anciennes)

1. **`get_access_status` (`GET /dataroom/{id}/access-status`)** : renvoyer API.md §4
   `{access_granted, access_status: null|'pending'|'accepted'|'granted'|'rejected'|'expired', steps:{identity, nda, funds}, next_step, request:{id, created_at, expires_at}}`.
   Repli actuel du front : `nda_signed`, `request.status` (`validated`/`loi_pending` = acceptée), identité lue sur `user.identity_verified` / `GET /kyc/status`.
2. **`POST /dataroom/{id}/funds-declaration {source: 'fonds-propres'|'emprunt'|'mixte'|'investisseurs', amount, financing_partner?}`** (route **absente** aujourd'hui) → `{access_granted:true}` ; pose `status:'granted'`, `granted_at`, `funds_declaration` ; 403 `nda_required` si le NDA n'est pas signé. Le formulaire est prêt (`FundsDeclarationForm`).
3. **`request_dataroom_access`** : accepter un corps facultatif `{message}` (le front l'envoie quand le repreneur écrit un mot), renvoyer `{request_id, status:'pending'|'accepted'}` (acceptation automatique si `auto_accept_dataroom` et score ≥ 50) ; exiger `profile_score ≥ 40` (403 `profile_incomplete`).
4. **`contact_company` (`POST /companies/{id}/contact`)** : accepter `{message}` (modèle Pydantic), créer la conversation `{company_id, buyer_id}` et le premier message, renvoyer `{conversation_id}` ; 403 `{code:'profile_incomplete'}` sous 40 ; carte repreneur au cédant. Le front navigue vers `/messages?conversation=<conversation_id>` (repli : `company_id`).
5. **`get_conversations`** : tableau API.md §3 `[{id, company_id, company_title, buyer_id, seller_id, other_party_label, last_message, last_at, unread_count, nda_signed, identity_revealed, access_status}]` ; le dictionnaire actuel est toléré (`normalizeConversations`) mais sans titre d'annonce (le front relit alors `GET /companies/{id}`).
6. **Alertes (`AlertCreate` / `AlertUpdate`)** : ajouter `trades: List[str]`, `regions: List[str]`, `rge: Optional[bool]` (API.md §8) et filtrer `trigger_alerts_for_company` sur `trades` / `regions` / `is_rge` / `max_price`. Le front envoie `{name, trades, regions, max_price, rge}` ; `name` reste renseigné pour le modèle actuel.
7. **`GET /offers/my`** : pour une offre `pending_signature`, renvoyer aussi `content` (texte du contrat) — ou exposer `GET /contracts/{contract_id}` (parties) — pour que « Signer mon offre » depuis le tableau de bord affiche le texte intégral. Aujourd'hui le front conserve le texte renvoyé par `POST /offers` en `sessionStorage` et, à défaut, affiche un résumé fidèle de l'offre (`offerSummaryText`) ; la signature porte toujours sur le contrat stocké côté serveur.
8. **`GET /companies/{id}`** : la fiche affiche `rge_validity` (date de fin déclarée) et `qualifications_verified_at` ; si `submit_listing` stocke le détail ADEME (`ademe_qualifications` : nom, organisme, `date_fin`), l'exposer sous ce nom dans l'annonce publique permettra d'afficher une date **par qualification** (le front lit déjà ce détail dans le diagnostic du dossier).
9. **`dataroom_access_granted` / `view_dataroom_document`** : textes « LOI » → « L'accès au dossier s'ouvre après l'accord de confidentialité et la déclaration d'origine des fonds » (déjà demandé par contrats-v2 §2.4).

## 3. Décisions et points d'attention

- **Une seule page de fiche** pour tous (visiteur, repreneur, cédant propriétaire, admin) : le cédant voit sa fiche « comme un repreneur » (nom et coordonnées exclus même s'ils sont renvoyés par l'API pour lui) avec un lien vers son espace ; un repreneur ayant signé le NDA voit le nom révélé en badge vert.
- **Encadré commission acquéreur** : uniquement `commission_info.payer === 'repreneur'` **et** `terms_version` v1 ou absente (`legacyBuyerPays` de `lib/mandate.js`) ; HT d'abord. Pour tous les autres cas, une seule phrase : `OFFER.payerSentence`.
- **Dates RGE** : l'annonce ne stocke qu'une date de fin (`rge_validity`) : elle est affichée sur chaque domaine avec la mention « date déclarée par le cédant pour sa qualification principale » ; le détail par qualification (organisme, dates ADEME) est dans le diagnostic du dossier. Aucun « Date non renseignée » : sans date, pas de pastille.
- **Signature d'une offre « à signer » plus tard** : voir §2.1 point 7.
- **Pipeline** : construit côté front à partir de quatre appels + un `access-status` par annonce (≤ 30) ; dès que `GET /messages/conversations` renverra `access_status` et `company_title` (API.md §3), `BuyerDashboard.load` peut s'en servir à la place des appels par annonce (`accessByCompany`).
- **Partage anonyme** : le lien public `/company/:id` ne contient rien d'identifiant ; le bouton utilise `navigator.share` (mobile) ou copie l'URL.
- Mobile : toutes les cartes `min-w-0`, listes à la place des tableaux, libellés de navigation masqués sous `md`, visionneuse plein écran ; aucun texte engageant sous 13 px (`text-xs` = 13 px via Tailwind).
